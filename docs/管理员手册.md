## 第1章 系统概述

### 1.1 平台介绍

Study Clash 是一个**基于 Flask 的游戏化学习对战平台**，核心理念是"让学习变得更有趣，让竞争激发潜能"。平台将学习与竞技结合，通过三种游戏模式（单人挑战、双人对战、四人挑战）激励学生主动学习，同时提供完善的管理后台供管理员和教师进行系统管理、内容维护和数据分析。

### 1.2 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端框架 | Flask | Python Web 框架，轻量高效 |
| ORM | SQLAlchemy | 数据库对象关系映射 |
| 实时通信 | Flask-SocketIO | 基于 WebSocket 的实时对战通信 |
| 数据库 | SQLite | 轻量级关系数据库，文件存储 |
| 前端 | Jinja2 + Bootstrap | 模板引擎 + UI 组件库 |
| 认证 | Flask-Login | 用户会话管理 |
| CSRF 防护 | Flask-WTF | 全局 CSRF 令牌验证 |
| 密码哈希 | Werkzeug | PBKDF2 安全哈希算法 |

### 1.4 角色与权限概览

系统定义了三种角色，各自权限边界如下：

| 角色 | 角色标识 | 权限范围 | 特殊说明 |
|------|----------|----------|----------|
| **管理员** | `admin` | 全部管理后台功能 | 豁免登录锁定机制；`is_admin` 字段自动同步 |
| **教师** | `teacher` | 8 项可配置细粒度权限 | 仅显示已授权的导航项 |
| **学生** | `student` | 仅前台功能 | 不可访问管理后台 |

#### 教师细粒度权限（8 项）

| 权限字段 | 权限名称 | 所属分组 | 说明 |
|----------|----------|----------|------|
| `can_manage_subjects` | 学科管理 | 内容管理 | 创建/编辑/删除学科 |
| `can_manage_chapters` | 章节管理 | 内容管理 | 创建/编辑/删除章节，导入导出章节 |
| `can_manage_questions` | 题目管理 | 内容管理 | 创建/编辑/删除题目 |
| `can_import_questions` | 题库导入 | 内容管理 | Excel 批量导入题目 |
| `can_export_questions` | 题库导出 | 内容管理 | 导出题目到 Excel |
| `can_import_students` | 学生导入 | 学生管理 | Excel 批量导入学生账号 |
| `can_view_student_analysis` | 学生分析 | 数据分析 | 查看学生学习数据 |
| `can_view_knowledge_analysis` | 知识点分析 | 数据分析 | 查看知识点掌握情况 |

> **提示**：管理员始终拥有全部权限，无需额外配置。教师权限由管理员在用户编辑页面通过开关控制。

## 第2章 快速开始 — 管理员初始化

### 2.1 首次登录

1. 启动应用后，浏览器访问系统地址（默认 `http://127.0.0.1:5002`）
2. 点击右上角**登录**，进入管理后台
3. 使用默认管理员账号登录：

```
用户名：admin
密码：admin123
```

> ⚠️ **安全警告**：首次登录后系统将强制跳转密码修改页面（`must_change_password` 标记为 `True`），**必须立即修改默认密码**，否则存在严重安全风险。

4. 修改密码后，`must_change_password` 标记自动清除，进入管理后台首页

### 2.2 基础配置步骤

完成首次登录后，按以下顺序进行初始化配置：

1. **系统设置** → 设置网站名称、描述、Logo
2. **安全设置** → 启用密码策略、配置登录锁定参数
3. **字典管理** → 配置学校、年级、专业、班级选项（供注册和个人资料使用）
4. **学科管理** → 创建学科（如数学、英语、物理等）
5. **章节管理** → 为各学科创建章节层级（章 → 节 → 小节）
6. **题目管理** → 手动创建或 Excel 批量导入题目
7. **用户管理** → 创建教师账号并分配权限

## 第3章 仪表盘与数据统计

### 3.1 仪表盘

管理后台首页（`admin.index`）展示系统核心指标：

| 指标 | 含义 |
|------|------|
| **总用户数** | 系统中所有注册用户总数 |
| **活跃用户数** | 状态为 `is_active=True` 的用户数 |
| **今日新增用户** | 当天注册的用户数 |
| **总游戏数** | 历史所有游戏房间总数 |
| **今日游戏数** | 当天创建的游戏房间数 |
| **总题数** | 系统中所有题目的数量 |
| **学科数** | 活跃学科的数量 |
| **系统运行状态** | 系统是否正常运行 |

> **提示**：仪表盘数据实时查询数据库，每次刷新页面获取最新数据。

### 3.2 数据统计

数据统计页面（`admin.statistics`）提供以下可视化分析：

- **答题趋势图**：按日/周/月维度展示答题数量变化趋势
- **游戏类型分布**：单人/双人/四人三种模式的占比
- **学科答题分布**：各学科的答题量分布
- **用户活跃度趋势**：日活/周活用户变化曲线
- **正确率统计**：整体正确率及各学科正确率

### 3.3 学生分析

学生分析页面（`admin.student_analysis`）供管理员和教师查看学生学习情况：

**功能列表**：
- 学生列表及筛选（按学校、年级、班级）
- 单个学生详情：答题历史、正确率、薄弱环节
- 学生对比分析
- 导出功能

**权限检查**：教师访问此功能需拥有 `can_view_student_analysis` 权限，否则提示"您没有此功能的权限，请联系管理员"。

### 3.4 积分审计

积分审计页面（`admin.points_audit`）记录所有积分变动：

**查询维度**：
- 按用户筛选
- 按时间范围筛选
- 按变动原因筛选

**积分变动原因**：

| 原因代码 | 中文说明 |
|----------|----------|
| `single_correct` | 单人答题正确 |
| `battle_win` | 双人对战胜利 |
| `four_first` | 四人挑战冠军 |
| `four_second` | 四人挑战亚军 |
| `four_third` | 四人挑战季军 |
| `four_fourth` | 四人挑战第四名 |
| `review_correct` | 错题复习正确 |
| `daily_login` | 每日登录 |
| `streak_bonus` | 连续答题奖励 |
| `admin_add` | 管理员添加 |
| `admin_deduct` | 管理员扣除 |

**管理员手动调整积分**：可在积分审计页面手动为用户添加或扣除积分，操作将记录为 `admin_add` 或 `admin_deduct` 原因。

## 第4章 用户管理

### 4.1 用户列表

用户管理页面展示所有用户的列表信息：

| 列字段 | 说明 |
|--------|------|
| 用户名 | 唯一标识，用于登录 |
| 昵称 | 显示名称，未设置则默认使用用户名 |
| 邮箱 | 唯一，用于登录和通知 |
| 角色 | admin / teacher / student |
| 状态 | 激活 / 禁用 |
| 积分 | 当前总积分 |
| 段位 | 当前段位名称 |
| 注册时间 | 账号创建时间 |

**筛选功能**：按角色、状态、学校、年级筛选  
**搜索功能**：按用户名、邮箱模糊匹配  
**分页浏览**：支持分页导航

### 4.2 创建/编辑用户

**基本信息**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 用户名 | String(64) | ✅ | 唯一，用于登录 |
| 邮箱 | String(120) | ✅ | 唯一，用于登录 |
| 密码 | String | ✅ | 创建时必填，编辑时留空则不修改 |
| 昵称 | String(64) | ❌ | 显示名称，默认使用用户名 |

**个人资料**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 真实姓名 | String(64) | `real_name` |
| 学号 | String(32) | `student_id` |
| 手机 | String(20) | `phone` |
| 学校 | String(100) | `school`，从字典数据选择 |
| 年级 | String(20) | `grade`，从字典数据选择 |
| 专业 | String(100) | `major` |
| 班级 | String(50) | `class_name` |
| 生日 | Date | `birthday` |

> **提示**：资料完整度判定 — 当 `real_name` 和 `student_id` 都填写时视为资料完整。

**角色与权限设置**：
- 选择角色为 `admin` 时，自动启用所有权限，隐藏权限配置区域
- 选择角色为 `teacher` 时，显示 8 项细粒度权限开关
- 选择角色为 `student` 时，隐藏权限配置区域

**状态管理**：
- `is_active=True`：激活状态，可正常登录
- `is_active=False`：禁用状态，登录时提示"账户已被禁用"

### 4.3 教师权限配置详解

当用户角色为 `teacher` 时，管理员可在用户编辑页面配置以下 8 项权限：

#### 内容管理组（5 项）

| 开关 | 权限名称 | 控制范围 |
|------|----------|----------|
| `can_manage_subjects` | 学科管理 | 学科的创建、编辑、删除操作 |
| `can_manage_chapters` | 章节管理 | 章节的创建、编辑、删除、导入导出操作 |
| `can_manage_questions` | 题目管理 | 题目的创建、编辑、删除操作 |
| `can_import_questions` | 题库导入 | Excel 批量导入题目功能 |
| `can_export_questions` | 题库导出 | 导出题目到 Excel 功能 |

#### 学生管理组（1 项）

| 开关 | 权限名称 | 控制范围 |
|------|----------|----------|
| `can_import_students` | 学生导入 | Excel 批量导入学生账号 |

#### 数据分析组（2 项）

| 开关 | 权限名称 | 控制范围 |
|------|----------|----------|
| `can_view_student_analysis` | 学生分析 | 查看学生学习数据和详情 |
| `can_view_knowledge_analysis` | 知识点分析 | 查看知识点掌握情况分析 |

> **提示**：教师缺少某项权限时，对应导航项不显示；若直接访问无权限的 URL，系统返回 403 错误。

## 第5章 内容管理

### 5.1 学科管理

**学科列表展示字段**：名称、编码、描述、图标、状态、创建者

**操作说明**：

| 操作 | 说明 |
|------|------|
| 创建学科 | 填写名称、编码（唯一）、描述、图标 |
| 编辑学科 | 修改描述、图标、启停状态 |
| 删除学科 | 需确认，若有关联章节和题目会提示存在关联数据 |

**学科模型字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | String(50) | 学科名称，唯一 |
| `code` | String(20) | 学科编码，唯一 |
| `description` | Text | 学科描述 |
| `icon` | String(100) | 图标标识 |
| `is_active` | Boolean | 是否启用，默认 True |
| `created_by` | Integer | 创建者用户 ID |

> **权限要求**：教师需拥有 `can_manage_subjects` 权限。

### 5.2 章节管理

章节采用**三级层次结构**：

```
章（level=1）→ 节（level=2）→ 小节（level=3）
```

**章节模型字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `subject_id` | Integer | 所属学科 ID |
| `parent_id` | Integer | 父章节 ID，顶级为 NULL |
| `name` | String(100) | 章节名称 |
| `level` | Integer | 层级：1=章，2=节，3=小节 |
| `order` | Integer | 排序序号 |
| `description` | Text | 描述 |
| `is_active` | Boolean | 是否启用 |

**展示方式**：树形结构，完整路径示例：`数学 > 函数 > 二次函数`

**操作说明**：
- **创建/编辑章节**：选择父级、设置名称、级别、排序、描述
- **章节导入**：支持 Excel 批量导入，系统自动解析层级关系
- **章节导出**：导出当前学科章节结构到 Excel
- **导入模板下载**：提供标准 Excel 模板

> **权限要求**：教师需拥有 `can_manage_chapters` 权限。  
> **约束**：层级仅支持章/节/小节三级，不支持更深层级。

### 5.3 题目管理

#### 5.3.1 四种题型

| 题型代码 | 题型名称 | 答题方式 | 正确答案格式 |
|----------|----------|----------|------------|
| `single` | 单选题 | 从 A-F 选择一个选项 | 单个字母，如 `A` |
| `multiple` | 多选题 | 从 A-F 选择多个选项 | 逗号分隔，如 `A,B,C`，完全匹配 |
| `judge` | 判断题 | 选择"正确"或"错误" | `T`/`F` 或 `对`/`错` |
| `fill` | 填空题 | 输入框输入答案 | 支持 `\|` 分隔多个可接受答案，如 `北京\|Beijing` |

> **提示**：填空题的 `|` 分隔符对用户不可见。系统判定时忽略首尾空格，只要用户输入匹配任一答案即判对。

#### 5.3.2 四个难度等级

| 难度值 | 难度名称 |
|--------|----------|
| 1 | 简单 |
| 2 | 中等 |
| 3 | 困难 |
| 4 | 极难 |

#### 5.3.3 题目字段详解

| 字段 | 类型 | 说明 |
|------|------|------|
| `subject_id` | Integer | 所属学科 |
| `chapter_id` | Integer | 所属章节 |
| `question_type` | String(20) | 题型：single/multiple/judge/fill |
| `difficulty` | Integer | 难度：1-4 |
| `content` | Text | 题干内容 |
| `image_url` | String(256) | 题干图片 |
| `option_a` ~ `option_f` | Text | 选项 A-F 文字 |
| `option_a_image` ~ `option_f_image` | String(256) | 选项 A-F 图片 |
| `correct_answer` | String(50) | 正确答案 |
| `analysis` | Text | 答案解析 |
| `points` | Integer | 题目分值，默认 10 |
| `time_limit` | Integer | 答题时限（秒），默认 60 |
| `is_active` | Boolean | 是否启用 |

#### 5.3.4 题库导入导出

**导入**：
- Excel 批量导入，支持多种变体格式
- 提供标准导入模板（`final_template.xlsx`）下载
- 权限要求：`can_import_questions`

**导出**：
- 导出题目到 Excel，含选项和答案
- 权限要求：`can_export_questions`

**筛选**：按学科、章节、题型、难度、状态筛选题目

**分页**：题目列表支持自定义每页显示数量，可在页面底部的"每页显示"下拉框中选择 10/20/50/100/200 条，默认 20 条/页。切换每页数量后会自动跳转至第 1 页，且保持当前筛选条件不变。

> **权限要求**：基本操作需 `can_manage_questions` 权限。

## 第6章 游戏管理

### 6.1 游戏模式

| 模式代码 | 模式名称 | 最大玩家数 | 说明 |
|----------|----------|------------|------|
| `single` | 单人挑战 | 1 | 独自答题，3 次错误机会 |
| `battle` | 双人对战 | 2 | 实时 PK，比拼速度和正确率 |
| `four` | 四人挑战 | 4 | 4 人同台竞技，按排名分配积分 |

### 6.2 游戏记录管理

**游戏记录列表字段**：

| 字段 | 说明 |
|------|------|
| 游戏类型 | single / battle / four |
| 学科 | 游戏涉及的学科 |
| 玩家 | 参与游戏的用户 |
| 得分 | 游戏得分 |
| 正确数 | 答对的题目数 |
| 错误数 | 答错的题目数 |
| 用时 | 总答题用时（秒） |

## 第8章 安全功能

### 8.1 登录锁定机制

系统对非管理员用户的连续登录失败实施锁定：

| 配置项 Key | 默认值 | 范围 | 说明 |
|------------|--------|------|------|
| `max_login_attempts` | 5 | 3-10 | 最大连续失败次数 |
| `lockout_duration` | 30 | 5-60 | 锁定时长（分钟） |

**工作流程**：
1. 用户登录失败 → `LoginAttempt.fail_count` 加 1
2. 当 `fail_count >= max_login_attempts` → 锁定账户 `lockout_duration` 分钟
3. 锁定期间尝试登录 → 提示"账户已锁定，请 X 分钟后重试"
4. 锁定时间到期 → 自动解锁，重置失败计数
5. 登录成功 → 重置失败计数和锁定状态

> ⚠️ **管理员豁免**：管理员（`role='admin'`）的登录失败不计入锁定机制。

### 8.2 密码复杂度策略

| 配置项 Key | 默认值 | 范围 | 说明 |
|------------|--------|------|------|
| `password_policy_enabled` | false | — | 策略总开关 |
| `password_min_length` | 8 | 8-32 | 最小密码长度 |
| `password_require_uppercase` | true | — | 需要大写字母 |
| `password_require_lowercase` | true | — | 需要小写字母 |
| `password_require_digit` | true | — | 需要数字 |
| `password_require_special` | true | — | 需要特殊字符 |

**策略未启用时**：仅要求最少 6 个字符

**策略启用时**：必须满足所有启用的规则，否则返回具体不符合项错误信息

**前端实时校验**：注册和修改密码页面通过 `/auth/api/password-policy` API 获取当前策略配置，实时显示密码要求。

### 8.3 管理员密码重置（CLI）

当管理员忘记密码时，可通过命令行工具重置，无需登录系统：

```bash
flask reset-admin-password
```

**交互流程**：
1. 输入管理员用户名
2. 输入新密码（输入时不显示明文）
3. 确认新密码
4. 系统校验密码是否符合策略要求，通过后更新密码

**注意事项**：
- 重置后 `must_change_password` 标记为 `True`，首次登录时强制修改密码
- 该操作会记录安全审计日志
- 仅限 `role='admin'` 的用户可被重置

### 8.4 CSRF 防护

- 系统使用 Flask-WTF `CSRFProtect` 进行全局 CSRF 防护
- 所有 POST 请求必须携带 `csrf_token`
- 模板中通过 `{{ csrf_token() }}` 注入令牌

### 8.5 文件上传安全验证

#### 扩展名白名单

仅允许以下格式：**PNG / JPG / JPEG / GIF / SVG**

#### Magic Bytes 校验

系统读取文件头部字节验证真实文件类型，防止扩展名伪造。

#### SVG 安全检测

拒绝包含以下危险内容的 SVG 文件：
- `<script>` 标签
- 事件处理器属性（`onclick=`、`onerror=`、`onload=` 等）
- `<iframe>`、`<object>`、`<embed>` 标签
- `javascript:` 协议
- `<link>` 标签的 `href` 属性

#### 文件大小限制

```
MAX_CONTENT_LENGTH = 16MB
```

> ⚠️ 上传文件的 Magic Bytes 与扩展名不匹配时，系统拒绝上传。

### 8.6 XSS 防护

- 聊天消息使用 `markupsafe.escape` 进行 HTML 转义
- Jinja2 模板默认开启自动转义
- 用户输入在存储和展示时均经过处理

### 8.7 请求限流

系统使用**基于内存的滑动窗口算法**进行请求限流：

| 接口 | 限流规则 | 说明 |
|------|----------|------|
| 注册接口 | 同一 IP 每 60 秒最多 3 次 | 防止批量注册 |
| 登录接口 | 同一用户名/IP 每 60 秒最多 5 次 | 防止暴力破解 |

**超限响应**：HTTP 429 + `Retry-After` 头 + 提示信息

### 8.8 生产环境密钥安全

生产环境必须在 `.env` 文件或环境变量中设置强随机 `SECRET_KEY`。

**不安全密钥黑名单**：

```
your-secret-key-change-in-production
dev
development
secret
change-me
flask-secret-key
test
```

- **生产环境**：使用默认/不安全密钥 → 直接抛出 `RuntimeError` 拒绝启动
- **开发环境**：使用默认密钥 → 仅发出警告

## 第10章 常见问题与故障排查

### 10.1 常见问题 FAQ

**Q: 忘记管理员密码怎么办？**

→ 在服务器命令行执行 `flask reset-admin-password`，按提示输入用户名和新密码即可重置。重置后首次登录会强制修改密码。
→ 如需恢复默认管理员账号（admin/admin123），可使用数据备份页面的"重置系统"功能。注意：此操作会清空所有数据！

**Q: 教师看不到某功能菜单？**

→ 检查该教师的权限配置。进入用户管理 → 编辑该教师 → 确认对应权限开关已开启。

**Q: 题库导入失败？**

→ 检查以下项目：
1. Excel 格式是否符合模板要求
2. 必填字段（学科、题型、题干、正确答案）是否完整
3. 题型值是否为 `single`/`multiple`/`judge`/`fill`
4. 难度值是否为 1-4 的整数

**Q: 数据库文件过大？**

→ 使用备份+重置+恢复流程：先创建备份 → 重置系统数据 → 仅恢复必要数据

**Q: 上传文件被拒绝？**

→ 检查：
1. 文件扩展名是否在白名单内（PNG/JPG/JPEG/GIF/SVG）
2. 文件大小是否超过 16MB
3. SVG 文件是否包含危险内容

**Q: WebSocket 连接失败？**

→ 检查：
1. `SOCKETIO_CORS_ALLOWED_ORIGNS` 配置是否包含客户端地址
2. 网络防火墙是否允许 WebSocket 连接
3. 浏览器是否支持 WebSocket

**Q: 生产环境启动报错 "RuntimeError: Insecure SECRET_KEY"？**

→ 在环境变量或 `.env` 文件中设置强随机的 `SECRET_KEY`，例如：`SECRET_KEY=$(python -c "import secrets; print(secrets.token_hex(32))")`

### 10.2 错误码说明

| HTTP 状态码 | 含义 | 常见原因 |
|-------------|------|----------|
| 400 | 请求参数错误 | 缺少必填字段、参数格式错误 |
| 403 | 权限不足 | 教师访问无权限功能 |
| 404 | 资源不存在 | 房间码无效、用户不存在 |
| 429 | 请求过于频繁 | 触发限流（注册/登录过快） |
| 500 | 服务器内部错误 | 程序异常，查看服务器日志 |
